# 硬件原理图 → Markdown 编写规范

> **用途**：本规范面向"读取原理图 PDF 并产出 Markdown 文档"的 AI 模型（视觉/多模态）。
> 目标产物：`docs/hardware-schematic.md`（板卡硬件参考手册）。
> 本文件同时是验收标准：产物不满足第 6 章检查清单 = 不合格，必须返工。

## 1. 输入物特性（实测，必须先读）

`docs/STM32G474R开发板-原理图--202508.pdf`

| 属性 | 实测值 | 对提取的影响 |
|---|---|---|
| 页数/版式 | 3 页，A4 横向（842×595pt） | 每页一个完整原理图区域 |
| 文本层 | **无**（get_text 为空） | 文字全部是矢量曲线，**直接复制/PDF 文本提取不可行** |
| 图片层 | 无（无嵌入位图） | 不能靠图片直取 |
| 矢量对象 | 每页 3000~3500 个（线/矩形/曲线） | 需先渲染成位图再视觉识别，或 OCR |

**结论**：必须先渲染为高分辨率 PNG，再逐页/逐区域视觉识别。渲染命令：

```bash
# PyMuPDF 渲染，300 DPI 足够读文字；看不清的小字局部用 600 DPI 重渲染
python - <<'EOF'
import fitz
doc = fitz.open("docs/STM32G474R开发板-原理图--202508.pdf")
for i, page in enumerate(doc):
    page.get_pixmap(matrix=fitz.Matrix(300/72, 300/72)).save(f"/tmp/sch_p{i}.png")
EOF
```

- 识别顺序：**每页先整体看一遍**（确认是电源页/主控页/接口页），再放大局部读细节
- 同一网络/同编号器件跨页出现时，**必须跨页比对确认一致**

## 2. 产物文档结构（模板）

产物写入 `docs/hardware-schematic.md`，必须包含以下章节，顺序固定：

```markdown
# 硬件原理图参考（<板卡名/版本号>）

> 来源：docs/STM32G474R开发板-原理图--202508.pdf（3 页）
> 提取日期：<YYYY-MM-DD>；识别不确定项标注 ⚠️（见 4.3）

## 1. 板卡概览
（一句话定位：主控型号、板卡形态、主要功能块列表）

## 2. 电源树
（输入电源 → 各 DCDC/LDO → 各电压域，含器件型号、输入输出电容、使能/指示）

## 3. 时钟
（外部晶振/振荡器：频率、负载电容、引脚；时钟源选择）

## 4. MCU 引脚连接总表
（**核心章节**，格式见 3.1）

## 5. 外设接口
（每类一个子节：调试、UART、CAN、SPI、I2C、USB、ADC 输入、PWM/电机、其他）

## 6. 板载器件与功能
（LED、按键、测量点、跳线、EEPROM、传感器、驱动芯片等，含器件型号与连接引脚）

## 7. 保护与安全电路
（过流/过压/反接/EOSD/刹车等，含触发逻辑）

## 8. 与现有文档的差异对照
（与 docs/pinmap.md 不一致处必须列出）
```

## 3. 格式规范

### 3.1 引脚连接总表（每行一条连接）

| 列 | 要求 | 示例 |
|---|---|---|
| MCU 引脚 | `PA8`/`PB1` 大写，禁止 `pa8` | `PA8` |
| 引脚功能 | 复用功能名或信号名（`AF1_TIM1_CH1` / `GPIO_OUT` / `ADC1_IN5`） | `AF1_TIM1_CH1` |
| 网络名 | 原理图上的网络标签，无标签写 `-` | `PWM_UH` |
| 连接对象 | 器件位号+引脚名（`U1.8` / `J2.3` / `LED1.A`），无位号写器件类型 | `U2(DRV8353).INH_A` |
| 方向 | `IN`/`OUT`/`BIDIR`/`PWR`/`NC` | `OUT` |
| 备注 | 上拉/下拉、串联电阻、滤波、电平转换等 | `10k 上拉至 3V3` |

- 表格按引脚号排序：PA0…PA15, PB0…PB15, PC0…PC15, PD0…PD2
- 未连接引脚单独一行 `NC`；不确定的引脚不猜测，见 4.3

### 3.2 器件表（每类器件一张表）

| 列 | 要求 |
|---|---|
| 位号 | 原理图上的 Reference（U1/R1/C1…），无位号写 `-` |
| 型号/标称 | 芯片写完整型号；阻容写标称值；无丝印写 `-` |
| 封装 | 芯片写封装（如 QFN48）；阻容写 0402/0603 等，看不清写 `-` |
| 连接 | 关键引脚连接（电源芯片写输入/输出/使能；驱动芯片写电源/逻辑引脚） |
| 备注 | 功能角色、特殊要求 |

### 3.3 通用规则

- 数值与单位：`3V3`/`5V`/`12V`（电压域）、`24MHz`/`16MHz`/`8MHz`（晶振）、`10kΩ`/`100nF`（阻容，允许 `10k`/`100n`）、`1kΩ@100kΩ` 分压写比例
- 网络名保持原理图原样（大小写/下划线不更改）
- 一切描述使用**本项目语言惯例**：中文叙述 + 英文技术名词（与 AGENTS.md 代码规范无关，文档层惯例）
- 禁止编造：器件型号看不清就写 `-` 并标 ⚠️

## 4. 提取纪律（最重要，违反即不合格）

1. **识别优先于推断**：只写图上看得见的内容。图上看不见的一律不写。
2. **禁止猜测型号/参数**：看不清的丝印、阻值、网络名 → 标 ⚠️ 并写 `-`，不得根据经验"补全"
3. **禁止臆造连接**：引脚连接必须能在图上找到对应网络/走线；找不到的连接不写
4. **明确区分事实与推断**：推断内容必须写在"备注"列并加前缀 `推断:`，或放入第 8 章差异对照
5. **交叉验证**：同一网络在不同页/不同位置出现时，多次出现的连接必须一致；不一致 → 标 ⚠️ 并说明
6. **电源与地**：每个电压域必须写清来源（哪个芯片哪路输出）与去向（哪些引脚/器件）；电源芯片反馈电阻网络必须记录阻值（可推算输出电压）

## 5. 输出节奏

1. 先渲染 PNG，逐页整体浏览，在回复中说明"第 N 页是什么功能页"
2. 按页推进，每页先给出该页器件/网络清单（供人工确认），再填详细表格
3. 全部完成后运行第 6 章自检清单，把自检结果附在产物末尾

## 6. 验收自检清单（产物末尾必须附结果）

| # | 检查项 | 结果 |
|---|---|---|
| 1 | 电源树完整：每个电压域有来源（芯片+引脚）与去向 | ☐ |
| 2 | 时钟：晶振频率/负载电容/引脚齐全，时钟源选择明确 | ☐ |
| 3 | MCU 引脚总表覆盖**全部**引脚（含 NC 行），无遗漏 | ☐ |
| 4 | 调试接口（SWD/JTAG/串口）引脚与连接完整 | ☐ |
| 5 | 所有 LED/按键/跳线/测量点已收录 | ☐ |
| 6 | 保护电路（若有）的触发条件与动作已描述 | ☐ |
| 7 | ⚠️ 项数量已统计并逐条列出（不得静默吞掉） | ☐ |
| 8 | 与 docs/pinmap.md 的差异已写入第 8 章 | ☐ |
| 9 | 无任何凭经验"补全"的型号/参数/连接 | ☐ |

自检不通过项必须返工补齐，不得带着未通过项交付。

## 7. 产出后的下游动作（本仓库约定）

- 产物 `docs/hardware-schematic.md` 评审确认后，**回填冻结** `docs/pinmap.md`（电机预留段按实际原理图定稿）
- bsp/ 引脚配置（gpio.c / 时钟）以冻结后的 pinmap 为准，修改需 `dev.py build` + `dev.py verify` 验证
- 硬件相关改动在提交说明中注明验证方式
