# 加密算法采用小型手写实现（AES-128-ECB / SHA-256 / HMAC-SHA256）

参考协议要求 AES-128-ECB（PKCS7 补齐）与 HMAC-SHA256（MAC），而 STM32G474 无硬件加密加速器（仅 RNG）。评估 mbedTLS 裁剪（~30–60KB flash，有社区安全审计）与手写小型实现（~10KB，智能表行业惯例）后，决定采用**手写小型实现**：只实现协议所需的三个原语（不自创密码构造），密钥体系（主密钥/会话密钥派生、默认/客户双态）严格按参考协议执行。

Status: accepted (2026-08-15)

## Considered Options

- **mbedTLS 裁剪**：维护性好、社区审计充分，且未来 CAT1 场景可能演进到 TLS。否决原因：当前协议固定无需 TLS 演进；flash 与静态分析（MISRA）负担；裁剪配置本身就是维护成本。
- **手写小型实现（选定）**：体积小、行业惯例、完全可控；风险 = 安全代码自维护。

## Consequences

- 风险缓解（必须执行）：① 仅实现协议所需原语，不发明任何密码构造；② NIST/公开测试向量全量验证；③ 代码走审查；④ **模块隔离**——`sec_` 接口稳定，替换为 mbedTLS 的成本 = 换一个模块。
- 若未来协议需要 TLS（CAT1 高带宽、HTTPS 等场景），本 ADR 可 supersede，重新评估 mbedTLS。
